# 추천과 코스 선택 알고리즘

입력은 출발 장소 ID 또는 좌표, 카테고리, 구·군, 랜덤성, 요청 개수 등이다. 추천 응답은 장소, 점수 내역, 이유, 직선거리와 교통 검증 상태를 반환한다. 코스 응답은 여기에 방문 순서와 저장에 사용할 수 있는 토큰을 추가한다.

1. `RecommendationInputValidator`와 추천 서비스가 좌표 조합과 출발지를 확인한다. `RecommendationCandidateFilter.select`는 구·군과 좌표 조건을 DB에 전달하고, ONLY에서만 선택 카테고리를 SQL 필터로 적용한다. 현재 후보 한도는 설정값 안에서 요청 개수에 따라 결정하며 기본 상한은 200건이다.
2. 후보를 정규화된 이름으로 한 번 줄이고 출발 장소 자체를 제외한다. 사용 가능한 좌표와 거리를 확인한다. Haversine은 지구 표면의 두 좌표 사이 직선거리 근사에 사용한다.
3. `RecommendationScorer`가 선호, 거리, 다양성, 데이터 품질에 기본 가중치 30/30/15/15를 적용한다. 교통 평가를 점수에 사용할 수 있으면 기본 가중치 10을 포함한다. 평가하지 못한 경우 해당 항목을 분모와 분자에서 함께 제외한다.
4. 맞춤 코스와 즉흥 룰렛은 추천 후보를 재사용한다. `CourseCandidateSelector`는 동일 ID와 잘못된 좌표를 제거한 뒤 역할 다양성을 고려한다. 선호·포함 모드에서 가능한 카테고리 역할을 첫 단계에 반영하고 나머지를 채운다.
5. `CourseOrderingService`는 가까운 지점부터 방문하는 기준 코스를 만든다. 허용 거리 이내의 순열 중 음식점 연속, 같은 역할 연속, 총 직선거리 순서로 비교한다. 최대 5곳이라 후보 순열은 120개 이하다.

## 코스 선택 의사 코드

거리 계산 코드에서 두 지점의 라디안 위도를 φ₁, φ₂, 라디안 경도 차를 Δλ, 위도 차를 Δφ라 한다. `a = sin²(Δφ/2) + cos(φ₁) × cos(φ₂) × sin²(Δλ/2)`를 구해 0~1 범위로 제한하고, `2 × atan2(√a, √(1−a))`로 중심각을 복원한다. 여기에 지구 반지름 6,371km를 곱한다. 같은 지점의 결과가 0에 가깝고 지점 순서를 뒤집어도 같은 거리가 나오는지는 `DistanceCalculatorTest`가 검증한다.

```text
후보 = 점수화된 추천 결과에서 유효 좌표와 서로 다른 장소 ID 확보
선택 = 선호 또는 포함 모드가 요청한 역할 중 가능한 후보 우선 포함
반복: 요청 개수를 채우거나 후보가 모두 소진될 때까지
    가능한 경우 새 역할 후보를 우선 비교
    randomness가 0이면 점수와 역할 보너스로 결정
    그 외에는 randomness로 후보 범위와 가중치 지수를 결정
    당첨 후보를 결과에 추가하고 남은 후보에서 제거
거리 상한을 지키며 방문 순서를 결정
```

룰렛 가중치는 `max(1, score + 1)^exponent × 역할 보정`이다. 지수는 랜덤성이 커질수록 낮아지고, 새 역할이면 1.35배를 사용한다. 시드를 제공하면 같은 입력·후보 순서에서 결과를 재현할 수 있다. 기본 즉흥 룰렛이 받는 최근 장소 목록과 함께 비교할 경우 최근 이력도 입력 조건의 일부다.

교통 데이터가 일부뿐이면 추천을 유지하며 검증 수준을 표시한다. 코스의 직선 연결은 실제 도로 경로를 나타내지 않는다. 시간과 비용을 확정할 원천 데이터가 없는 경우 추정 상태는 `UNKNOWN`이다.
