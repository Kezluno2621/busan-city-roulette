## 2. 실행 및 종료

프로젝트 루트 PowerShell에서 권장하는 최소 실행 절차는 다음 한 명령이다.

```powershell
.\scripts\demo\run-demo.ps1 -Username root -AllowEmptyPassword
```

실행기는 시연용 MySQL 시작, 백업 및 기준 데이터 검증, Spring Boot 시작을 순서대로
수행한다. `Started CityRouletteApplication` 로그가 나타나면 Chromium에서
`http://127.0.0.1:18090/`에 접속한다. `Ctrl+C`와 `Y`로 종료하면 `finally` 블록이
이 실행기가 시작한 demo MySQL까지 종료한다.

단계별 복구가 필요할 때만 다음 명령을 사용한다.

```powershell
.\scripts\demo\start-demo-db.ps1
.\scripts\demo\verify-demo.ps1 -Username root -AllowEmptyPassword
.\scripts\demo\start-demo.ps1 -Username root -AllowEmptyPassword
.\scripts\demo\stop-demo-db.ps1
```

현재 복제본은 빈 로컬 root 비밀번호를 사용하므로 명시적인 `-AllowEmptyPassword`가
필요하다. 다른 장비에서는 파일에 비밀번호를 쓰지 말고 `DEMO_DB_USERNAME`과
`DEMO_DB_PASSWORD` 환경변수를 사용한다.

## 5. Chromium 핵심 시나리오

실제 브라우저 자동 조작에 걸린 시간은 약 3분 33초였다. 발표 설명과 화면 전환을 포함하면
5~7분 구성이 적절하다.

1. 메인 화면에서 서비스 목적과 주요 동작 소개
2. 관광지 목록에서 `APEC` 검색과 `해운대구` 지역 필터 적용
3. 검색 결과 1건의 상세 페이지, 좌표 기반 Leaflet 지도, 주소와 출처 확인
4. DB 기반 출발지 검색 후 개인화 추천 실행
5. 추천 결과 10건과 추천 점수·이유 확인
6. 카테고리 3종, 장소 5개, seed 42로 룰렛 코스 생성
7. `베지나랑 → 다온 한정식 → 부산시청자미디어센터 → 수영 돼지국밥 → 다리집 본점`
   결과에서 음식점 3곳 연속이 발생하지 않음을 확인
8. 잘못된 비밀번호 오류 안내 후 `demo` 계정 로그인
9. 룰렛 코스 저장 및 내 코스 상세/방문 순서 확인
10. 장소 즐겨찾기 등록 및 개인 목록 확인

브라우저 새로고침 뒤에도 로그인 세션이 유지됐다. 발표 후 리허설에서 추가한 코스와
즐겨찾기는 삭제하여 다음 실행이 동일한 기준 상태에서 시작하도록 했다.

| 상황 | 실제 결과 | 발표 대응 |
| --- | --- | --- |
| MySQL 미실행 | 검증 스크립트가 친절한 오류로 중단 | `start-demo-db.ps1` 후 `verify-demo.ps1` 재실행 |

| API 키 누락 | DB 검색·추천·룰렛 정상, ODsay는 안전한 오류 안내 | ODsay/실시간 기능은 보조 기능으로 설명 |
| 잘못된 로그인 | 사용자용 오류 메시지 표시 | `demo` 계정으로 다시 로그인 |

| MySQL 재시작 | 395건 및 회원 데이터 유지 | 시작 후 반드시 `verify-demo.ps1` 실행 |
| 지도 타일 연결 실패 | 완전 오프라인 네트워크 차단은 미검증 | 텍스트 장소 정보와 추천/룰렛을 시연하고 지도는 외부 타일 의존임을 설명 |

Leaflet 코드와 OpenStreetMap 타일은 인터넷에 의존한다. 인터넷 연결 상태에서는 지도와
마커를 확인했다. 네트워크 어댑터를 실제로 끈 완전 오프라인 Chromium 시연은 수행하지
않았으므로 성공으로 표시하지 않는다. DB 기반 관광지 검색, 추천, 룰렛, 저장은 외부 관광
API 키 없이 실제 검증했다.
