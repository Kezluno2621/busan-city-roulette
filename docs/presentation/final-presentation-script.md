# City Roulette 10장 발표 대본

전체 발표 6분, 시연 5분을 기준으로 한다.

## 1장. 표지 (20초)

“City Roulette는 부산 공공 관광데이터를 통합하고, 사용자의 취향과 출발지를 기준으로
장소와 여행 코스를 추천하는 Spring Boot 웹 서비스입니다. 현재 실제 관광 장소 395건을
기반으로 검색, 추천, 룰렛, 회원별 저장까지 구현했습니다.”

## 2장. 문제와 사용 흐름 (35초)

“여행지를 정할 때 사용자는 장소 검색, 지도 확인, 후보 비교를 여러 서비스에서 반복합니다.
이 과정을 즉흥 룰렛과 맞춤 코스 추천 두 기능으로 단순화했습니다. 즉흥 룰렛은 입력을
최소화하고, 맞춤 코스는 출발지와 지역, 선호 카테고리를 반영합니다.”

## 3장. 관광지 탐색 (30초)

“장소 395건을 서버 측 페이지네이션으로 조회합니다. 키워드, 카테고리, 부산 구·군 필터를
DB 쿼리에 적용하기 때문에 전체 데이터를 브라우저로 보내지 않습니다. 각 장소에는 출처와
이미지 라이선스를 보존하고, 표시 조건이 불분명한 이미지는 대체 이미지로 처리합니다.”

## 4장. 시스템 구조 (35초)

“웹 요청은 Controller, Service, Repository의 3계층으로 분리했습니다. 추천과 코스 생성은
Service가 담당합니다. 공공데이터 수집기는 서버 시작 시 실행되지 않는 별도 수동 Runner로
구성해 웹 서비스와 대량 수집을 분리했습니다.”

## 5장. 공공데이터 통합 (45초)

“TourAPI, 부산명소, 부산맛집, 갈맷길 네 공급자를 통합했습니다. API 응답을 공통 DTO로
정규화하고 좌표와 주소를 검증합니다. 동일 공급자의 externalId는 갱신하고, 다른 공급자의
유사 장소는 자동으로 합치지 않습니다. 같은 조건으로 재수집했을 때 중복 증가가 0건임을
확인했습니다.”

## 6장. DB 설계 (35초)

“places는 화면에서 사용할 대표 장소를 저장하고 place_sources는 공급자 식별자와 라이선스를
보존합니다. 회원은 코스와 즐겨찾기, 여행 기록을 소유합니다. 버스 노선과 정류장은 정차 순서를
가진 연결 테이블로 표현했습니다. 스키마는 Flyway V1부터 V12까지 재현 가능합니다.”

## 7장. 추천과 룰렛 (55초)

“추천 점수는 카테고리와 거리, 다양성, 데이터 품질, 검증 가능한 교통 정보를 사용합니다.
교통 데이터가 부족하면 추천을 제거하지 않고 해당 가중치를 제외합니다. 룰렛은 점수가 높은
장소의 선택 확률을 높이는 비복원 추출을 사용하고, 같은 seed에서는 같은 결과를 재현합니다.
역할 그룹 다양성을 적용해 음식점만 연속되는 문제도 줄였습니다.”

## 8장. 구현 화면 (25초)

“왼쪽은 맞춤 코스 입력과 추천 결과, 가운데는 서버가 선택한 결과와 일치하는 즉흥 룰렛,
오른쪽은 로그인 회원이 저장한 코스 화면입니다. 모든 화면은 실제 Chromium에서 확인했습니다.”

## 9장. 검증 결과 (35초)

“현재 전체 자동화 테스트 334개가 통과합니다. MySQL 8과 Flyway V12 환경에서 데이터 복원,
서버와 DB 재시작 후 보존, 360픽셀 모바일부터 데스크톱까지 반응형 화면을 확인했습니다.
기능 테스트와 실제 브라우저 검증을 구분해 기록했습니다.”

## 10장. 한계와 발전 방향 (30초)

“버스 데이터는 100번 노선 일부 구간이므로 부산 전체 경로를 검증했다고 말할 수 없습니다.
실제 이동시간과 요금도 원천 데이터가 없어 계산하지 않습니다. 다음 단계에서는 전체 정적
노선망과 운영시간 데이터를 확보하고 배포 환경의 보안을 추가 검증할 계획입니다.”

## 시연 전환 문장

“이제 로컬 demo 환경에서 관광지 검색부터 맞춤 코스, 즉흥 룰렛과 회원별 저장 순서로
핵심 흐름을 보여드리겠습니다.”
